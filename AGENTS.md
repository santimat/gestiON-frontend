# AGENTS.md — gestiON-frontend

React 19 + Vite 8 + TypeScript SPA (stock & sales management). UI copy, comments, and error messages are in **Spanish — keep them Spanish**.

## Commands

- Dev server: `pnpm dev`
- Typecheck: `npx tsc -b` (no dedicated script; `pnpm build` = `tsc -b && vite build`)
- Lint: `pnpm lint` (`eslint .`)
- No test framework, no CI, no format script. Prettier config exists (`.prettierrc` = defaults + `prettier-plugin-tailwindcss`); run `npx prettier --write <files>` only on files you touched — repo-wide it would reformat tab-indented files.
- just commit when the dev says that you have

**Package manager:** `pnpm` (`pnpm-lock.yaml` + pnpm-layout `node_modules`). `package-lock.json` is a stale duplicate — do not run `npm install` or update it.

**Baseline is green** — `npx tsc -p tsconfig.app.json --noEmit` and `pnpm lint` both finish with **0 errors**. Keep it that way: if a run comes out red, it's a regression to fix before moving on. (Before 2026-10-15 it was red with 3 `tsc` errors — `ProductSearch.tsx` importing a never-created `@/mocks/posMocks`, `productMapper.ts(7)` `string` vs `number`, `ProtectedRoute.tsx(8)` unused `allowedRoles` — and 1 lint error for that same `allowedRoles`. Confirmed green again on 2026-10-28 after the sale-discount + commerce `name` changes.)

Note: `npx tsc -b` (and `pnpm build`) also type-checks `tsconfig.node.json`. Running tsc with `--skipLibCheck false` surfaces one pre-existing error inside `@mantine/hooks` (`ReadonlySetLike`), not our code.

## Architecture

Feature-based layout. Each resource lives in `src/features/<recurso>/` with its own `components/ pages/ schemas/ services/ stores/ hooks/ mappers/ types.ts` (+ `constants.ts` and `index.ts` barrel when needed). The reusable shell lives in `src/shared/` (`components/ pages/ layout/ routes/ hooks/ services/ utils/ config/ schemas/ types.d.ts`). Features: `auth`, `cashiers`, `categories`, `clients`, `commerces`, `landing`, `offers`, `products`, `sales` (POS `components/sell/` + `pages/Sell.tsx` + `useSaleStore`, and history `components/sales/` + `pages/Sales.tsx` + `useSalesStore`), `sell-points`.

Data flow: feature `pages/`/`components/` → feature `hooks/useX.ts` → feature `stores/useXStore.ts` (zustand) → feature `services/<x>Service.ts` → `backendAPI` (axios). Each feature's `stores/` holds `useXStore.ts` plus a `types.d.ts` with the store's `UseXStore` interface (imported by alias: `@features/<x>/types`).

- Path aliases: `@/`, `@shared/`, `@features/` → `src/`, `src/shared/`, `src/features/` (wired in both `vite.config.ts` and `tsconfig.app.json`). **Prefer `@features/` and `@shared/`** — the `@/features/...` and `@/shared/...` forms were normalized away on 2026-11-03.
- **Import rules:** every import uses an alias — no relative paths (`./`, `../`) anywhere in `src/` (normalized 2026-11-03): `@features/<x>/...` for anything inside a feature (deep paths allowed **only from within `<x>` itself**), `@shared/...` for the shell, `@/...` for `src/` root files. A feature may consume **another** feature **only through its barrel** `@features/<recurso>` (`index.ts` — never deep-import another feature's internals). (`@shared/` importing features is tolerated only for shell data needs like `SideBarFooter` → `@features/auth`/`@features/commerces`. `App.tsx` lazy-importing pages with full paths is the documented exception.)
- Types: each feature exports its domain types from `features/<x>/types.ts` (zod `z.infer` next to its schemas); cross-cutting types (`AppError`, `FieldErrors`, `NavItem`, `UserRole`, `ZodParseResult`) live in `src/shared/types.d.ts` (`@shared/types`). The old global `src/types.d.ts` is gone.
- Schemas live per feature (`features/<x>/schemas/`); the shared filter base is `src/shared/schemas/FiltersBaseSchema.ts`. There is no global schemas barrel.
- Backend: `http://localhost:8080/api`, hardcoded in `src/shared/services/axiosConfig.ts` with `withCredentials: true`. Auth is **HTTP-only cookie based** (no token in localStorage, no `.env` files — `import.meta.env` is unused). Backend must be running locally for anything networked.
- Routes are declared in `src/App.tsx` (lazy-loading pages from `@/features/<recurso>/pages/...`) with `ProtectedRoute`/`GuestRoute` wrappers. `ALLOWEDS_ROUTES_BY_ROLE` in `@shared/config/permissions.ts` is the **single source of truth for permissions**: both the sidebar filter and `ProtectedRoute` resolve roles through `getRolesForRoute(href)`, so they can't drift apart (a path that appears in no role is closed to everyone). `ProtectedRoute` waits for `hasHydrated` (see below), redirects anonymous users to `/` and wrong-role users to `/unauthorized`. Full-screen pages live in `src/shared/pages/`, outside both wrappers, lazy-imported like the pages: `NotFoundPage` (`*`), `UnauthorizedPage` (403) and `InProgressPage` (temporary view for `/dashboard`, also reachable at `/in-progress`).

## Conventions (differ from defaults)

- Import router APIs from **`react-router`** (v8). `react-router-dom` (v7) is also in `package.json` but unused — don't import it.
- `tsconfig.app.json` sets `verbatimModuleSyntax`, `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`: use `import type` for types, no enums/parameter properties, no unused anything.
- Named exports everywhere (`export const useX`, `export const XPage`); default exports only in `src/App.tsx` and `src/main.tsx`.
- Services pattern: zod `safeParse` → `handleZodParsingError` → request → catch with `if (isAxiosError(error)) throw handleAxiosErrors(error); throw error;` (never swallow an unknown error, or callers get `undefined` data). `handleAxiosErrors` **returns** an `AppError` = `{ code: keyof typeof ErrorDictionary, message, fieldErrors? }` and falls back to `NETWORK_ERROR` when there is no response (backend down) — codes and Spanish messages live in `src/shared/utils/errorDictionary.ts`. Callers catch and show `toast.error(appError.message)` (sonner), with a Spanish fallback string for non-`AppError` throws.
- Auth state (`src/features/auth/stores/useAuthStore.ts`) keeps a `hasHydrated` flag: `hydrateUser()` early-returns once hydrated, so `/auth/me` is called once per page load no matter how many guards mount. Route guards gate on `hasHydrated` (not on `isCheckingAuth`); `logout()` clears the session in a `finally` and also resets `hasHydrated`.
- Zustand selectors use `useShallow` (see the feature `hooks/` files).
- **Mobile/desktop rendering:** lists with two variants use `useIsMobile()` from `@shared/hooks/useMediaQuery` (matchMedia at 768px = Tailwind `md`) with an early return, so only the active variant mounts — no more `hidden md:block` / `md:hidden` pairs on list wrappers (the shell at `lg` is still CSS-only).
- Tailwind v4 CSS-first config: design tokens are `@theme` variables in `src/global.css` (no `tailwind.config`). Mantine 9 coexists (`MantineProvider` in `main.tsx`) — Mantine for structure/components, Tailwind for styling. Color tokens that actually exist: `background`, `background-soft`, `card`, `surface`, `border`, `input`, `foreground`, `secondary-foreground`, `primary`, `primary-soft`, `success`, `warning`, `destructive` (plus `font-display`, `shadow-card`, `shadow-raised`). **Trap:** shadcn-style names such as `text-muted-foreground`, `bg-accent`, `text-accent-foreground`, `text-primary-foreground` have no `--color-*` variable, so Tailwind emits nothing and the class silently no-ops — `text-primary-foreground` is already dead in `features/landing/components/Header.tsx`, `Footer.tsx` and `PreviewPanel.tsx` (verified against the built CSS). Map to an existing token (`text-secondary-foreground`, `hover:bg-background-soft`, Mantine sets a button's own foreground) or add the token to `@theme` first.
- Mantine `Button` with icons: `leftSection={<Icon />}`. For a link styled as a button use `<Button component={Link} to="...">` (type-checks fine with react-router 8) — avoid `<Button><Link …></Button>`, which nests an `<a>` inside a `<button>`; `features/landing/components/Hero.tsx`, `CTASection.tsx` and `Header.tsx` still do it, don't copy it into new code.
- **React Compiler is enabled** (babel preset in `vite.config.ts`): components auto-memoize, so skip manual `useMemo`/`useCallback`/`React.memo`. When writing/reviewing React code, load the `vercel-react-best-practices` skill (registered in `skills-lock.json`).
- **`usePageHeader` registra el contenido solo si cambió de verdad** (`useRef` + comparación campo-a-campo en `@shared/layout/hooks/usePageHeader.ts`): un re-render de la página con `title`/`subtitle`/`actions` idénticos no debe re-setear el store ni re-renderizar el header del shell; `clearHeader` corre únicamente al desmontar. Pasar JSX como `actions` depende del memo del compiler; si no está memoizado, cae en el comportamiento de siempre (set), nunca peor.
- **Fetch data where it's consumed, not in the page** — e.g. `SellPointForm` pulls `cashiers` from `useCashier` and fetches on mount, so the request only fires when the modal actually opens (Mantine `Modal` mounts children when opened). Don't prefetch lists "for the form" at page level like `SellPoints.tsx` used to (removed 2026-10-28); the zustand store keeps the data global anyway.
- **Modal close trap:** store close actions (`closeFormModal` in `useSellPointStore`, etc.) must only flip the `isOpen` flag — never null out the associated data (`formSellPoint`, `cashiersModalSellPoint`). Mantine keeps modal children mounted during the exit fade, so nulling mid-transition visibly resets the content (the `key` flips via `?.id ?? "create"` and inputs blank out). Clear the data in the `openX` action instead; it already overwrites it on every open (fixed 2026-10-28).
- **Sale discount contract** (aligned with `gestiON-backend` `SaleRequest`): `discountType: "FIXED_AMOUNT" | "PERCENTAGE"` + `discount: number > 0`, **both-or-neither** (zod `.refine` in `SaleRequestSchema` + backend 400 otherwise). Send them only when the draft has a discount; when sending, cap to match the `SaleSummary` preview exactly (`%` → `min(discount, 100)` — 100% is a valid "free" sale; amount → `min(discount, subtotal)`) so the registered total always equals what the cashier saw. Backend `PERCENTAGE` currently doesn't reject `> 100` via API (total would go negative) — the frontend cap is the only guard; backend-side fix pending. `Sale` responses return `discountType (nullable)` and `totalAfterDiscount`; the four backend discount error codes (`INVALID_DISCOUNT`, `DISCOUNT_WITHOUT_TYPE`, `TYPE_WITHOUT_DISCOUNT`, `DISCOUNT_EXCEEDS_SUBTOTAL`) are in `errorDictionary.ts`.
- **Commerce naming:** the commerce entity field is **`name`** everywhere in the API surface (`CommerceWithOwner.name`, `CurrentCommerce.name`, request keys for POST/PUT `/commerces*`) — renamed from `businessName` on 2026-10-28. The `business*` prefixed fields (`businessLogo`, `businessLogoUrl`, `businessActive`) keep their names. Don't reintroduce `businessName`.
- Skills live in `.agents/skills/` (registered in `skills-lock.json`): `vercel-react-best-practices` and `lovable-mcp` (how to drive the Lovable MCP). The Lovable project **Swift Stock** (`f20db5cf-bbb4-4695-aa42-e486aa2a9ef5`, workspace "santi's Lovable") is the design source this repo implements — read designs from it with `lovable.read_file` before building a view from scratch.
